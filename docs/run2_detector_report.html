Detector Run 2 — cleaner, not stronger

Retrained with the Run 1 data fixes. It didn't rescue crab-pot and didn't lift shipwreck or cylinder off their plateau — but it cut the false-alarm rate. That settles the class count and points the next work at Module 2.

Model YOLOv8s detection Epochs 120 · 2.85 h Test set 785 real + synth Speed 3.8 ms / frame Date 2026-08-31

The short version

Same detection coverage, meaningfully cleaner. Test mAP50 held at 0.61, but precision rose 0.69 → 0.73 and the false-positive rate fell 0.31 → 0.27.

Pipeline is now near-perfect (0.99 AP50, real data). crab-pot moved but stayed broken (0.12 → 0.19, still misses 71%). Shipwreck and cylinder didn't budge (~0.45, ~0.40) — that's a real-data-quality ceiling, not a training problem.

Decision: ship 4 classes, drop crab-pot per the pre-agreed rule. Build Module 2 next, before any further retrain — its numbers decide whether one last retrain is worth it.

04 Why shipwreck and cylinder are stuck

Both have real data. The problem is how little of it survives our pipeline, and how small the objects are.

Shipwreck — the tiling throws away ~90% of AI4Shipwrecks

Cylinder — the targets are tiny

Real MILCO boxes are 3–5% of the frame (~15–50 px). Sub-20 px objects are at the edge of what YOLOv8 at 640-pixel input can localise — the whole model's small-object recall is only 0.20. Only 315 real instances, and drawn-rectangle synthetics have the wrong acoustic signature (uniformly bright instead of bright-edge-plus-shadow).

Fixes: copy-paste augmentation from the real MILCO cut-outs (real signature, synthetic placement) rather than drawn shapes; fold in the NonMILCO contacts (+178 real instances — the PS asks for "cylinders", not "mines"); and train at 896 px input, which helps every small-object class at once.

05 Decisions going forward

  1. Ship 4 classes — drop crab_pot

    Test AP50 0.19 < the pre-agreed 0.25 threshold. Two runs and near-doubled data prove it's a separability problem, not a data-volume one. Method: filter class 0 at inference + set drishti.yaml nc: 4 — zero retrain. The four kept classes (pipeline, shipwreck, cylinder, ghost-net) map exactly onto the hazards the problem statement names.

  2. Keep crab_pot as an honest slide

    "Also trained a derelict-fishing-gear detector on real data; AP50 0.19; small low-contrast targets need dedicated small-object modelling — roadmapped." Reads as diligence, and crab pots are lost fishing gear, so it's on-theme.

  3. Build Module 2 next — before any retrain

    Confidence calibration (Platt scaling → honest 0–100%, ECE + reliability diagram) plus the shadow-geometry false-positive filter. Module 2 is also a measuring instrument: its per-class precision-at-recall and its FP-rate reduction tell us whether the shipwreck/cylinder problem is fixable downstream or needs better training data.

  4. Then decide: retrain once, or move on

    If calibration + shadow filter get shipwreck & cylinder to ~0.75+ precision at recall ~0.5 → skip the retrain, move on. If they stay under ~0.6 precision or the shadow check barely helps → one final retrain: re-tile AI4Shipwrecks with overlap, cylinder copy-paste + NonMILCO, imgsz 896. ~2.8 h unattended, doesn't block anyone.

Priority order — deadline 5 September

Modules 2 / 3 / 4  >  the data fixes + retrain  >  anything else. A working end-to-end pipeline with a 0.6 detector beats a 0.7 detector with no confidence scoring, no geotagging and no map UI. If the team can push only one track, push 3 & 4.
