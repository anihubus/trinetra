Cut false alarms, output an honest 0–100% score

Net: the per-class gate is Module 2's proven false-positive filter. Calibration is a quick fix away from being pitch-ready. The shadow check is wired and unit-tested but only meaningful on full transects with real ping geometry — which Module 3 now provides, but AURORA has no labels to score it.

What the real-data run proves — and what it exposes

Proves: the full pipeline runs on unseen real sonar (TIF → tiles → detect → filter → geotag → JSON/GeoJSON/CSV) in ~8 s, and Module 2 correctly suppresses noise (15 → 1, flagged for review not auto-confirmed).

Exposes: the model barely fires on AURORA — a different sonar instrument and seabed than any training source. It doesn't transfer without fine-tuning on the target survey. That's the honest deployment story, and the strongest argument for the retrain restart.

06 Where to review the flagged (pending_review) cases

  • Today (no UI yet): open <run>/report.csv or report.json and filter review_status == "pending_review". Each row has the sonar pixel bbox, the lat/lon, the ping_id (jump back to the exact ping), the timestamp, and the %.
  • Target — Module 4 Review Queue: frontend/src/components/ReviewQueue/ (scaffolded). Shows each pending detection as a sonar crop next to its map pin; the analyst clicks confirm or reject, which PATCHes review_status to analyst_confirmed / analyst_rejected in PostgreSQL.
  • The bands: <30% dropped (never shown) · 30–80% pending_review (goes to the queue) · ≥80% auto_confirmed (straight onto the map). Thresholds live in backend/reporting/schema.py.

Bottom line: the architecture is complete and every module runs. One capability is genuinely strong; two are usable-but-thin; the confidence and geotag layers work. The known gaps — data-limited classes, calibration refit, shadow-check validation, cross-survey transfer — are exactly what the preprocessing + retrain restart targets.

08 Then — the restart

  3. Redo Module 2 — per-class calibrators on the new model, re-run eval_module2.py.
  4. Compare — preprocessed-model pipeline vs this raw-model baseline, same test protocol.
