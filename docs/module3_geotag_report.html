Geotagging & reporting — first run

The engine that turns a detection box in a sonar image into a latitude, a longitude, a size in metres, and a structured JSON/CSV report. Built and validated against the AURORA survey — position agrees with the recorded navigation to under a metre.

Fixture AURORA JC125/M87 SSS Nav rows 92,450 · 12.8 h XTF parse 8,000 pings / 0.10 s Unit tests 6 / 6 Date 2026-08-31

The short version

It works. Two independent navigation paths — a minimal XTF ping-header parser and the survey's coordinate CSVs — both produce geotagged JSON, CSV and GeoJSON reports, each record carrying an audit pointer back to its source ping.

Position is validated. The XTF-parsed lat/lon/heading match the recorded navigation.csv to under 1 m at the same timestamp. Six unit tests pin the projection geometry.

One number to calibrate: the across-track scale. With the real slant range from the XTF (107.7 m) the two paths still differ by ~120 m because the CSV-only path was run with a 50 m default. Fix: always read the range scale from the XTF or the image's georef tags.

01 What Module 3 has to do

Problem statement: "reads sonar metadata (such as coordinate files or ping headers) to output a structured report (JSON or CSV) … the exact location (latitude/longitude), bounding dimensions, and classification of each detected hazard."

Our approach: parse the navigation once into two lookup tables, then project every detection through the sonar geometry.

05 Moving forward with these results

  1. Wire into the backend job

    In backend/detections/tasks.py: detector → confidence_filter → geotag() → save DetectionRecords to PostgreSQL → push over the WebSocket. The report exporters are already the JSON/CSV the API contract promises.

  2. Unblock Module 2's shadow check

    The XTF parser now yields per-ping altitude and slant range — exactly what ShadowVerifier.compute_penalty was waiting on. Feed those into the confidence pipeline and measure the false-positive reduction on real geometry.

  3. Feed Module 4's map

    report.geojson is a plain FeatureCollection of points with class, confidence and review status — drop it straight into the Leaflet layer. Clicking a pin shows the ping_id and timestamp for the auditability requirement.

  4. Close the two approximations

    Pull the swath range scale from the XTF (done for that path) or the TIF georef tags (for the CSV-only path). Check the row↔ping relationship on one real TIF and replace the linear assumption if it's off.

Priority unchanged

Module 3 core is done. Next: wire-up + Module 2 shadow check on real geometry, then Module 4 swaps mock → live. The detector retrain still goes last — it changes none of this.
