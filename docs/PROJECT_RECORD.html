01The problem

Problem Statement 26057 (Ministry of Earth Sciences / NIOT) asks for an end-to-end computer-vision pipeline that ingests side-scan sonar (SSS) imagery, finds man-made debris against a complex natural seabed, and produces actionable, located data. The hazards it names: shipwrecks, pipes, cylinders, and entangled debris nets — “ghost nets,” the abandoned fishing gear that keeps killing marine life for decades.

Manual review of thousands of kilometres of sonar logs is slow and error-prone, and debris hides among rock fields, sand ripples and ridges. The system has to cope with what acoustic imaging does to a scene — speckle noise, varying pixel resolution, acoustic shadows, and data dropouts from vehicle heave, pitch and roll — and it has to run on the edge, on or near an autonomous underwater vehicle, without a cloud in reach.

The four deliverables

#ComponentWhat it must do
1Detection / segmentation modelDraw boxes (or masks) around man-made objects — shipwrecks, pipes, cylinders, nets.
2Confidence & noise filteringMinimise false positives from shadows and rock clusters; output a clear 0–100 % score per detection.
3Reporting & geotaggingRead sonar metadata / ping headers → structured JSON/CSV report with lat/lon, size, class per hazard.
4UI dashboardUpload a raw sonar log, view detections on a map in real time, download the report.

02How we approached it

Four reasoning steps took us from the brief to a concrete architecture.

1 — Detection, not classification

The report needs the location of each hazard, not just “this tile contains debris.” That rules out a plain classifier and points at an object detector that returns a box per object.

2 — Why YOLO, and why not the alternatives

ArchitectureEdge speedOutputVerdict for DRISHTI
Faster R-CNN~5–10 FPS (two-stage, heavy)boxestoo slow for on-board use
Standalone U-Net~15 FPS, resource-heavysemantic masksemantic, can't separate two overlapping nets
YOLOv8s~40–260 FPSinstance boxesreal-time · mature ONNX/TensorRT export · anchor-free

YOLOv8 small specifically: ~11.8 M parameters fits a 6 GB laptop GPU at a usable batch size, and its export path to ONNX (and onward to a Jetson TensorRT engine) is battle-tested — newer YOLO variants often introduce ops the edge compilers don't yet support.

3 — Boxes now, masks as a roadmap

The PS accepts “bounding boxes or pixel-level masks.” Every real SSS dataset we could obtain is box-labelled; the only pixel masks (AI4Shipwrecks) have a published benchmark we can cite for the segmentation roadmap. So: box detection, and a deterministic geometry check — not a second network — as the “verify” stage.

4 — The pivot: forward-looking sonar → pure side-scan

The two-stage idea

Stage A (YOLOv8) is a fast scout that proposes boxes. Stage B is a deterministic check: does the object's acoustic shadow have the length that sonar geometry predicts for something of its apparent height, at that range and altitude? A rock cluster fails it. No second network, no extra training data. The physics is in §10.2.

03Data strategy

Labelled SSS imagery of specific debris is scarce — there is no public real dataset of ghost nets in side-scan. So the training set is assembled from many real surveys, one class at a time, with synthetic fill only where reality offers nothing.

04Run 1 — the first detector

Five classes, YOLOv8s fine-tuned from COCO, 120 epochs on the RTX 4050. SSS-specific augmentation from the start: colour jitter off (grayscale), vertical flip off (it would invert the highlight→shadow relation), and brightness / scale / random-erase jitter mapped to real sonar nuisances (gain, resolution spread, motion dropouts).

How the shipwreck number reads against the literature

Two 2026 papers benchmark the same AI4Shipwrecks data (§12). A single-class YOLO on a clean split tops out at mAP50 ~0.72–0.76 (DFSE-YOLO; vanilla YOLOv8 0.716); human annotators agree only 50–60 % (SW-Net). Our figure is that ceiling minus a deliberately harder test set and multi-class dilution. The failure modes are the field-standard Type I (false positives on rock / ripple / shadow) and Type II (misses on buried, nadir-gap or collapsed hulls); a calibrated 50 px box-merge (§14) is the named route to close the gap.

Verdict: preprocessing gave no accuracy gain

On a matched protocol the models are statistically indistinguishable — identical precision, identical false-positive rate, mAP within noise, pipeline and net unchanged. A clean ablation: the detector learns effective denoising from raw pixels plus augmentation. The restart's data changes were kept; preprocessing is retained only because CLAHE'd input makes acoustic shadows more detectable (shadow-presence separation 0.23 → a 0.10 gap).

09Edge deployment — ONNX export

An AUV has no GPU and no room for a 1.5 GB PyTorch runtime. The deployment target is an ONNX graph run by onnxruntime — a ~50 MB runtime with a numpy + opencv pre/post path and no PyTorch import at all.

Theory — what an ONNX export is, and what precision costs

Training frameworks store a model as code + weights. ONNX is a framework-neutral computation graph: the same conv / add / sigmoid ops, serialised, so a lean C++ or Python runtime can execute them without the training library. Ops get fused (Conv + BatchNorm + activation → one kernel) and constant-folded on export.

Precision. Weights are 32-bit floats. FP16 halves the size and, on a GPU with half-precision units (a Jetson), roughly doubles throughput at negligible accuracy cost. INT8 maps each tensor to 256 integer levels via a learned scale (calibrated by pushing ~100 real tiles through and recording activation ranges) — 4× smaller, and much faster on hardware with INT8 acceleration (VNNI / AVX-512 / a TensorRT engine). Without that hardware, the quantise/dequantise nodes make it slower, and on faint sonar targets the coarse levels can collapse the class scores entirely.

Measured — three precisions on the laptop CPU

ModelSizeCPU latencyAccuracy (test, torch-free path)Role

Decision

Ship FP32 ONNX. 45 MB is trivial for an AUV; the meaningful bar is torch-free, GPU-free, survey-speed — and ~11 tiles/s against a sonar producing a few pings/s clears it. FP16 is the Jetson deployment (recommended edge precision). INT8 is excluded — no CPU speed-up and it destroyed accuracy on faint sonar targets, exactly the known risk; a usable INT8 engine would need quantization-aware training or head-excluded PTQ, a research task. The 2026 literature (DFSE-YOLO) assumes FP32→INT8 transfers cleanly with “proportional” loss — our measurement is the counter-evidence for faint sonar targets.

10The modules — theory, physics & architecture

Each module below: the idea and the physics it rests on, then the flow it's implemented as. Modules 0–3 are functional; Module 4 is scaffolded (§14).

0
Preprocessing
reduce acoustic speckle without erasing the edges that carry the signal

Theory & physics

A side-scan image is not formed by light but by coherent acoustic backscatter. Within one resolution cell many sub-wavelength scatterers return echoes that add with random relative phase. The result is speckle: noise that is multiplicative, not additive —

observed intensityIobs(x) = Itrue(x) · n(x)    with   E[n] = 1  (n follows a gamma / Rayleigh law)

A plain averaging filter suppresses n but also blurs Itrue — and the edges it blurs (object outlines, shadow boundaries) are exactly what a detector keys on. Two adaptive operators fix that:

Lee filter — a local linear minimum-mean-square-error estimate. In a window around each pixel it forms the local mean μ and variance σ², then outputs

Lee (MMSE) updateÎ(x) = μ + W · ( I(x) − μ )     W = σ²signal / ( σ²signal + σ²noise )

In flat seabed the local variance is almost all noise → W → 0 → the output is the smoothed local mean. On an edge the local variance is dominated by real structure → W → 1 → the pixel is left alone. One filter, edge-aware by construction. This division of labour matches an observation from the SSS literature: the high-resolution shallow layers of a CNN on sonar largely model speckle rather than structure (Lin et al. 2026, §12), so cleaning the input and letting the deeper layers carry the semantics is the right split.

CLAHE (contrast-limited adaptive histogram equalization) — histogram equalization stretches intensities to fill the range, lifting faint contrast; done globally it also amplifies speckle in near-uniform sand. CLAHE equalizes per 8×8 tile (bilinearly blended across tile borders) and clips each tile histogram at a ceiling before equalizing, redistributing the clipped mass. The clip caps the local gain, so a faint wreck edge is boosted while flat-sand speckle is not blown up.

Slant-range / time-varying-gain correction is not applied here: a cropped tile has no reliable swath geometry. It belongs on the full transect, where the ping altitude and range scale are known (§10.3). A second fixed-geometry cleanup — masking the nadir gap, the dead band directly under the fish where G → 0 — is a cheap way to drop a known false-positive region (after SW-Net) and is on the roadmap (§14).

What the ablation showed

With strong training-time augmentation, this front-end denoising produced no accuracy change (§08). A CNN with enough augmentation learns an equivalent internal filter. Preprocessing is kept only because CLAHE'd input makes shadows measurably more detectable, which helps Module 2's shadow logic.

Architecture

1
Detection
a box + class + score for every man-made object in a tile

Theory

Transfer learning. Training a detector from scratch needs millions of images. Instead we start from COCO-pretrained weights — the early convolutional filters already encode edges, gradients and part/whole composition, which transfer to any imagery. Fine- tuning re-specialises the later layers on sonar. This is why ~4,900 tiles is enough. Cross-domain pretraining on unrelated natural imagery is established practice for small SSS datasets — four independent studies (§12) show it beats training from scratch, which plateaus near 80 % accuracy, and it stabilises convergence. We start from COCO rather than a sonar corpus like SeabedObjects-KLSG, which Du et al. 2023 found transfers worse than generic ImageNet because its object types don't match the target.

YOLOv8 structure. Three parts:

  • Backbone — a CSP-Darknet convolutional stack; extracts feature maps at strides 8, 16 and 32 (fine → coarse).
  • Neck — a PAN-FPN that fuses those three scales top-down and bottom-up, so a small cylinder and a swath-spanning pipeline both survive to the head.
  • Head — decoupled (separate box and class branches) and anchor-free: it predicts each box edge directly as a probability distribution over positions (Distribution Focal Loss), rather than nudging pre-set anchor boxes.

Across the three scales there are ~8,400 candidate cells. Each predicts a box (4 numbers via DFL) and one independent sigmoid per class — multi-label, not a softmax, so a box can legitimately score on two classes. Training minimises CIoU (box position, size, aspect), BCE (class), and DFL (sharpen the edge distribution). At inference, a confidence floor plus non-maximum suppression (greedy suppression of overlapping same-class boxes above an IoU threshold) reduce the 8,400 to a handful.

Why the “small” variant: 11.8 M parameters / 28 GFLOPs fits a 6 GB GPU at batch 16, exports cleanly, and has enough feature-map depth to catch faint acoustic gradients that the nano variant loses. SSS adaptations: colour augmentation off (single channel); vertical flip off (it would swap the highlight→shadow polarity the model must learn).

Two known weak spots, both on the roadmap (§14). CIoU degrades on extreme-aspect boxes (our pipelines) and on low-quality labels (our mask-derived shipwreck boxes) — the WIoU v3 loss is the published mitigation (Jiang et al. 2024), at zero inference cost. And in a multi-class model a dominant class with distinctive features can suppress accuracy on feature-dissimilar classes (Du et al. 2025, §12) — the reason we cap every class per split rather than let pipeline volume dominate.

Architecture

2
Confidence & noise filtering
cut false alarms, and turn the raw score into an honest 0–100 %

Theory & physics

Calibration. A network's raw sigmoid output is a score, not a probability — a “0.8” is not right 80 % of the time. Platt scaling fits a one- parameter logistic on held-out (score, correct/incorrect) pairs:

Platt scalingP(correct | s) = 1 / ( 1 + exp( a·s + b ) )     a, b fit on the validation split

We fit one calibrator per class, because the score↔accuracy relation differs sharply: a pipeline detection at raw 0.30 is ~61 % likely correct, a crab-pot at raw 0.80 only ~30 %. Quality is the Expected Calibration Error — bin the calibrated scores, and average the gap between predicted confidence and observed accuracy per bin:

ECEECE = Σbins ( nb / N ) · | accuracyb − confidenceb |   →   0.052 raw → 0.037 calibrated

Per-class gate. Empirically the false positives of shipwreck and cylinder sit far below their true positives in raw score (mean FP ≈ 0.08 vs mean TP ≈ 0.5). A class-specific cut-off (pipeline 0.25, shipwreck / cylinder 0.40) removes most false alarms at a small recall cost.

Shadow-geometry check — the physics. A raised object of height h on a flat seabed, insonified from a sensor at altitude H and slant range R (so ground range G = √(R² − H²)), blocks the beam behind it. By similar triangles the geometric shadow length is

expected acoustic-shadow lengthL = h · G / ( H − h )     ( with G = √(R² − H²) )

A real raised object's measured shadow matches L. A rock cluster returns strongly but sits nearly flush (small effective h), so its predicted L is tiny — a large or absent measured shadow is geometrically inconsistent and the detection is demoted. This needs per-ping H and R, which Module 3 supplies. On cropped tiles with one assumed geometry the check can't discriminate (measured §08), so it is opt-in, active only on full transects.

Temporal persistence (planned, §14). On a full transect the overlapping tiles see each object several times; requiring a detection to recur across ≥ K overlapping windows removes one-off false positives (after GhostVision). The window size is set by a coarse-graining sweep — binning detections at doubling scales and finding where real objects cluster (after Cuff et al., §12).

3
Reporting & geotagging
turn a detection's pixel into a latitude, a longitude, a size in metres

Theory & physics

How a side-scan image is built. The tow-fish moves along a track. Each ping is a cross-track line: the return is sampled in slant range — round-trip travel time × sound speed ÷ 2. Directly below the fish (nadir) the slant range equals the altitude; the image column encodes increasing slant range outward. The image row is the ping index, i.e. along-track position / time.

Slant range → ground range. Assuming a flat seabed, an object seen at slant range R from a sensor at altitude H lies a horizontal distance

flat-bottom slant-to-groundG = √( R² − H² )     (near nadir G → 0, the "nadir gap"; at far range G → R)

Along-track fix. Image row → ping number → the navigation record's timestamp → interpolate the (latitude, longitude, heading) logged for that instant (heading interpolated the short way around the circle).

Across-track placement. The target is G metres from the track, perpendicular to the heading: bearing = heading − 90° for the port channel (left), + 90° for starboard (right). Then a geodesic forward step — from (lat, lon), move G metres along that bearing on a spherical Earth — gives the target coordinate (exact enough for the sub-kilometre offsets in side-scan). Box width and height convert to metres with the same across-track scale. This formulation follows the published side-scan ATR localisation maths of Yu et al. (2021, §12); our additions are the header-only XTF parser and the <1 m validation below.

Validation

On the AURORA survey, position recovered from the XTF ping headers agrees with the independently recorded navigation.csv at the same timestamp to latitude Δ ≈ 0.3 m, longitude Δ < 0.1 m, heading Δ 0.0°. Six unit tests pin the projection maths.

What the literature settles

  • Our shipwreck number is at SOTA, not broken. Single-class YOLO on a clean AI4Shipwrecks split tops out at mAP50 ~0.72–0.76 (DFSE-YOLO), human annotators agree only 50–60 % (SW-Net). Our lower figure is a deliberately harder test set (the overlap re-tile 3×'d the shipwreck instances) plus multi-class dilution.
  • COCO→sonar transfer learning is established practice. Four independent SSS studies (Qin, Du 2023, Du 2025, Yu): from-scratch plateaus ~80 %, pretraining adds ~10 pts and stabilises convergence. Even grayscale-CIFAR pretraining halves the error.
  • Dropping KLSG was right. Du et al. 2023 found KLSG a worse pretraining source than generic ImageNet — its object types don't transfer.
  • mAP can mislead. GhostVision's best-mAP model had 0.6 % precision. We report calibrated precision / recall / ECE at the operating point.
  • Cross-survey transfer needs fine-tuning — documented behaviour (GhostNetZero IoU 0.74→0.55), with the same remedy we propose.
  • Synthetic data has limits. It helps only when it matches the real feature distribution (Qin), and volume plateaus by ~1000 / class (Du 2025) — no public real ghost-net SSS dataset exists, which is why ours is physically modelled.
  • Heavy attention modules cost ~30 % of the frame rate on YOLOv8 — two independent sources (DFSE-YOLO, Jiang). We take only the zero-cost improvements for an edge target.
  • Our review queue is a proven design — the human-in-the-loop feedback loop deployed by Microsoft / WWF's GhostNetZero.

Literature posture — one paragraph for the viva

We benchmarked DRISHTI against the current side-scan literature. On AI4Shipwrecks the 2026 state of the art is SW-Net (IoU 0.39, segmentation) and DFSE-YOLO (mAP50 0.755 detection; vanilla YOLOv8 0.716); human annotators agree only 50–60 %. Our shipwreck performance sits in that band. Our confidence module follows GhostVision's finding that mAP overstates operational utility, so we report calibrated precision / recall at the operating point. Our geotagging follows the published Yu et al. (2021) formulation and validates to <1 m. Our review queue is the human-in-the-loop design deployed by Microsoft / WWF's GhostNetZero. Cross-domain pretraining is validated by four independent SSS studies; cross-survey transfer needs fine-tuning — a documented field-wide limitation with the same remedy. And INT8 quantization, which the literature assumes transfers cleanly, collapsed faint-target recall in our tests — so we ship FP32 ONNX, torch-free, at ~90 ms/tile on CPU.

14Directions ahead

  1. Module 4 — the dashboard biggest gap

    Upload a sonar log, run the pipeline, render report.geojson on a Leaflet map, feed the pending detections into the review queue, offer the JSON/CSV download. It exists as a scaffold on mock data; it is a required PS deliverable.

  2. Backend wiring

    Connect ml/inference/pipeline.py to the Django/Celery task → PostgreSQL → the WebSocket push. The API contract and report schema are fixed.

  3. The fine-tuning story

    The model doesn't transfer across surveys. Deployment answer: fine-tune on a small labelled sample of the operator's own sonar. Build and time that loop — it becomes a pitch strength.

  4. Shipwreck & cylinder

    Still the weak classes at ~0.4–0.45 on their own test sets. More AI4Shipwrecks-style surveys, real-object copy-paste augmentation for cylinders, or accept and document the ceiling.

  5. Adopt DFSE-YOLO's box-merge, then its selective enhancement from §12

    Replace the mask-close in tile_ai4shipwrecks.py with a 50 px / 1–2 m proximity box-merge (cross-validated F1 0.87 on 14 wrecks) and re-evaluate shipwreck. Longer term, selective deep-feature enhancement (C≥128 layers only) is the code-available path toward ~0.755 mAP50 at 40 FPS / 5 MB.

  6. Cheap eval upgrades for the deck from §12

    Scenario table (low-contrast / reverberation / complex-seabed bins × mAP, after DFSE-YOLO Table 3 and TR-YOLOv5's Sobel complexity descriptor); confusion matrix + class-balance analysis (Du 2025); Grad-CAM heatmaps over sonar tiles; confirm and report the site-disjoint AI4Shipwrecks split.

  7. Two zero-risk training experiments from §12

    WIoU v3 loss (1-file Ultralytics patch, targets the noisy shipwreck labels); a YOLOv8n 4-class export for a size/mAP point against the ~5 MB SSS-literature norm. Optionally a staged transfer (KLSG / raw-strip intermediate fine-tune) after Yu et al.

  8. Untapped real data from §12

    Marine-PULSE (Du et al., Zenodo 7922705) — 323 real pipeline/cable SSS images across five instruments — as extra submarine_pipeline data or an in-domain pretraining set.

  9. Multi-modal fusion (long term) from §12

    Bathymetry / magnetometer / multi-frequency channels to cut Type I errors — flagged by both SW-Net and Du et al. 2025 as the next step for seabed-object recognition.

  10. Prove the shadow check

    Wired and unit-tested but no quantified benefit — needs a labelled and geo-referenced transect to measure false-positive reduction on real geometry.

  11. Tier-1 edge number

    Borrow a Jetson, run the FP16 ONNX with the TensorRT execution provider, capture the on-vehicle latency. That's the deployment figure for the deck.

  12. Close Module 3's approximations

    Read the swath range scale from the XTF or TIF georef tags; check the row↔ping mapping on a real TIF; along-track object size needs ping-rate × speed.
